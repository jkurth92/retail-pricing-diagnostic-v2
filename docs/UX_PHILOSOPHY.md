# UX Philosophy

## Narrative-first

Users should understand the retailer’s pricing story from **executive summaries and structural themes** before encountering signals, pattern inventories, or ingestion mechanics.

The default journey presents:

1. Client context (setup)
2. Data & scope (setup)
3. Pricing profile → structural themes → opportunity → implications (readout)
4. Supporting diagnostics (evidence)

## Progressive disclosure

Detail is available but not default. Expandable sections use client-facing labels such as:

- View supporting signals
- View role assumptions
- View confidence details
- View opportunity rationale

## Calm, consulting-grade presentation

Whitespace, section headings, and narrative blocks should feel like a **strategic deliverable**, not an analytics dashboard or internal tooling console.

## Hide the machinery

Deterministic engines, overlap factors, and registry structures remain in code and docs — not in the primary UI. The user should feel the intelligence without reading framework layer names or engine step numbers.

## What we avoid

- Ontology-first navigation
- Dense KPI grids and status pill walls
- Repeated executive readouts on every workflow step
- Operational language (optimize, prescribe, match competitors)
