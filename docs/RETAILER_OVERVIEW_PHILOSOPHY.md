# Retailer Overview Philosophy

## Consulting overview, not a finance terminal

The retailer overview should read like a **short strategic briefing**:

- Who is the retailer (public/private, ticker, sector)
- Scale signals (revenue, stores, geography) when known
- A few relevant headlines
- Strategic context for the diagnostic conversation

It should **not** present raw API JSON, dense tables, or competitor price data.

## Enrichment vs diagnosis

| Enrichment | Diagnosis |
|------------|-----------|
| Company profile | Client uploads + pattern features |
| News headlines | Hypothesis engine |
| Scale display strings | Opportunity storyline (thematic %) |
| Archetype suggestions | Knowledge registry selections |

## Manual-first workflow

Consultants can:

- Enter retailer name and populate enrichment
- Override ticker and profile fields
- Refresh when needed
- Ignore suggestions and keep manual archetype/posture

## Peer context

Competitor suggestions remain **local seed data** for optional market framing. They are not fetched via API and do not affect opportunity sizing.
