# Contextual Expectations (Step 14B)

## Interpretation language

The engine produces **consulting-style** phrases:

- “below the expected range”
- “narrower than typical”
- “broader than expected”
- “consistent with leading [archetype] structure”

It does **not** use pass/fail, threshold breach, or optimization target language.

## Example

**Observed:** Premium/Mainstream gap 8%  
**Expected (Mass, Hi-Lo):** 15–30%  
**Result:** Evidence for compressed architecture is **strengthened** — narrative references archetype and posture.

## Category-specific framing

Category sensitivity profiles adjust how compression in Beauty vs Grocery is described (premiumization vs KVI traffic), without changing the engine into a rules table in the default UX.

## Maturity adjustment

EPR average (when provided) scales interpretation severity:

- **Higher maturity** → structural gaps weighted as more commercially meaningful
- **Lower maturity** → some gaps (e.g. zoning coherence) weighted slightly less aggressively

## Traceability

Benchmark context appears in:

- `ComputedEvidenceBundle.benchmarkCalibration`
- Opportunity calculation trace → **“Compared to expected structure”** (expandable, secondary)

## Confidence interaction

- Strong measured evidence + below-expected structure → credible thematic opportunity (bounded)
- Weak evidence → widen modestly or suppress via existing confidence gating (Step 14A)
- Within-expected structure → slightly tighter thematic bands (avoid over-claiming)
