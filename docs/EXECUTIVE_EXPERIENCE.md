# Executive Experience

## Default mode

The app opens in **executive journey mode**: a single coherent diagnostic path without module tabs for pricing / promotions / markdown (those remain deferred).

Each readout step shows:

- A short **context strip** (retailer type, posture, objectives, category lens)
- One **primary narrative section** from the Step 7 deliverable engine
- **Expandable evidence** only when the user asks for it

## Architecture-first storytelling

Structural themes and profile copy emphasize **architecture and role coherence** before promotional or markdown themes — matching the storyline engine order.

## Readout steps (3–6)

| Step | Primary content |
|------|-----------------|
| Pricing profile | Inferred structure, architecture notes, maturity (scoring in disclosure) |
| Structural themes | Top themes with optional signals and full hypothesis list |
| Opportunity overview | Margin hero, sensitivity prose, drivers in disclosure |
| Strategic implications | “What this means” bullets and storyline in disclosure |

## Supporting diagnostics (7)

Secondary material only: pattern inventory, full hypotheses, ingestion tables, peer context — each behind disclosure.

## Header

The page header shows retailer name, profile line, and thematic margin range — not engine status or framework configuration pills.

## Why not a dashboard

Dashboards optimize for metric scanning. This product optimizes for **boardroom narrative**: bounded ranges, coherent themes, and explicit non-prescriptive guardrails.
